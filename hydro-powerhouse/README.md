# みずのちから！ひかるタービン

4歳児向けの、文字を読まなくても遊べる水力発電所3Dゲームです。

> 羽根をつけて、水を通して、大きな機械を回し、町を光らせる。

灯台・山の列車・夜の町から電気を届けたい場所を選び、タービンと発電機を組み立て、水門を開いて電気を送ります。点数、制限時間、ゲームオーバー、数値入力はありません。操作に失敗しても進行不能にならず、全工程を一本指で完結できます。初回プレイ時間の設計目標は約3〜5分です。

## 起動

配布版はビルド不要です。Node.js で同梱の静的サーバーを起動します。

```sh
cd hydro-powerhouse
npm run dev
```

ブラウザで次を開きます。

```text
http://127.0.0.1:8341/
```

ポートを変える場合は次のように指定できます。

```sh
node tools/serve.mjs --host 127.0.0.1 --port 9000
```

ゲーム本体の実行にパッケージのダウンロードや外部通信は不要です。自動検証を行う場合だけ、後述の開発依存関係を `npm install` で準備してください。

## あそびかた

主要な入力は約11操作です。画面内で光って揺れる大きな対象を、タップ、ドラッグ、または長押しします。

1. 灯台・列車・夜の町の絵から、電気を届けたい場所を1回タップする。
2. 大きなタービン羽根を空きスロットへドラッグする。
3. 2枚目の羽根をドラッグする。
4. 3枚目の羽根をドラッグする。残りは補助工程で補完され、9枚のランナーが少し回る。
5. 太い銅コイルを発電機リングの溝へドラッグする。
6. 2個目のコイルをドラッグする。
7. 3個目のコイルをドラッグする。残りが決定論的に補完され、12個のリングが完成する。
8. 黄金色の潤滑油ホースを接続口へドラッグする。サイトグラスの油面が上がる。
9. 青い冷却水ホースを接続口へドラッグする。透明管に流れと泡が現れる。
10. クレーンで吊ったケーシングを機械へドラッグする。近づくと吸着し、下降して固定される。
11. 水門レバーを長押しする。離すと開度の上昇が止まり、もう一度押すと続きから開く。

最後は選んだ場所だけが点灯・始動します。完成後も水門を弱めたり再び強めたりでき、タービン速度と明るさの変化を確かめられます。右下のリプレイボタンで最初から遊び直せます。

## 8フェーズ

| フェーズ | 子どもの主動詞 | 画面で起きること |
|---|---|---|
| `chooseDestination` | えらぶ | 灯台・列車・夜の町から、送電先を絵で選ぶ |
| `runner` | はめる | 羽根3枚を手で置き、残りを補完して9枚のタービンを完成させる |
| `stator` | はめる | 銅コイル3個を置き、残りを補完して12個の発電機リングを完成させる |
| `fluids` | つなぐ | 潤滑油と冷却水の2本のホースを順に接続する |
| `casing` | 下ろす | クレーンのケーシングを合わせ、巨大機械として閉じる |
| `gate` | 開く | 押している間だけ水門が開き、水流と回転が連続して強くなる |
| `generation` | 届ける | 発電機から送電線へ光の脈動が走る |
| `complete` | 光らせる | 選んだ設備だけが動き、最終場面で水門を再操作できる |

カメラは自由操作ではなく、工程ごとの映画的な固定ショットです。横画面は左の水から中央の機械、右の送電先へ因果を流し、縦画面は貯水側、タービン、発電機／送電先を上から下へ積む別ショットです。回転時には現在の工程と配置済み部品を保持したまま即座に再構図します。

## 技術構成

- Three.js r170相当を `vendor/three.module.min.js` に同梱し、Import Mapでローカル読込
- WebGL2を看板体験の基準とする静的HTML／ES Modules構成
- ビルド工程なし、外部CDNなし、実行時の外部アセット要求なし
- `src/main.js`：8フェーズ、Tween、入力ロック、縦横別カメラ、進行状態、`window.__hydro`
- `src/world.js`：発電所セット、貯水・水門・機械・クレーン・技術者・保守ロボット・3送電先、軽量な水／油／発光表現
- `src/radial-assembly.js`：羽根とコイルの `InstancedMesh`、固定seed、行列更新、時間差補完、容量検証
- `src/interaction.js`：一指Pointer入力、広いヒット領域、ドラッグ吸着、長押し、ヒント、画面座標ターゲット
- `src/plant-layout.js`：設備、通路、人物、クレーン経路、縮尺、占有領域、衝突余白を扱う純粋で決定論的な配置契約
- `src/audio.js`：WebAudioによる音楽・効果音・環境音バス、残響、位置音源、水量・回転数に追従する連続音、ミュート状態
- GPU端末では小画面のdevicePixelRatio上限を1.25、それ以外を1.5に制限。ソフトウェアWebGL2では検証を安定させるため0.25に下げ、PBRの色・発光・透明度を軽量な非照明材へ同期
- 反復する羽根、コイル、飛沫はインスタンス化し、影を落とす物と粒子数を制限
- タブ非表示時は更新を停止し、復帰時の時間差を破棄して状態を維持

`node_modules` と Playwright は検証専用であり、公開ゲームの実行時依存ではありません。

## `window.__hydro` デバッグ契約

画面には表示されない、自動検証向けの読み取り専用APIです。オブジェクト本体は凍結され、`window.__hydro` は上書き・再定義できません。ゲーム進行を直接変更するデバッグコマンドは公開していません。

| プロパティ／関数 | 内容 |
|---|---|
| `phase`, `busy` | 現在の8フェーズと、カメラ／入力ロック状態 |
| `targets()` | 現在操作できる対象。`id`, `phase`, `action`, `x`, `y`, `rect`、ドラッグの `dropX`, `dropY`, `dropRect`、長押し時間、方向、送電先を返す |
| `selectedDestination`, `destination` | 最初に選んだ `lighthouse`／`train`／`city` |
| `runner` | 手動配置数、設置済み数、総数、容量、完了状態 |
| `stator` | 手動配置数、設置済み数、総数、容量、完了状態 |
| `fluids` | 現在の接続工程、油・冷却水の接続、油面、流量、残りの泡 |
| `casing` | 設置状態、位置合わせ、下降進捗 |
| `gate` | 水門開度と長押し状態 |
| `turbine` | 正規化した回転速度 |
| `generation` | 発電状態、正規化出力、送電進捗、到達先、各送電先の効果 |
| `destinationEffects`, `transmissionReached` | 灯台・列車・町の点灯／動作の排他状態と、送電到達状態 |
| `finalSceneComplete`, `complete`, `replayVisible` | 最終場面とリプレイUIの状態 |
| `audio` | ミュート、モード、3バス、残響、位置音源、イベント統計 |
| `renderer` | draw calls、triangles、points、lines、pixel ratio、WebGL2、メモリとシーン統計 |
| `camera`, `composition` | 現在のショット、FOV、縦横、カメラ座標と、主要ランドマークの画面座標 |
| `layout`, `validation` | 発電所配置統計、衝突・縮尺・アセンブリ容量の検証結果 |
| `diagnostics`, `suspended` | 入力、カメラ、Pointer、Tween、ページ非表示中断の診断情報 |

## 自動検証

初回のみ検証用依存関係を準備し、別ターミナルで静的サーバーを起動します。

```sh
cd hydro-powerhouse
npm install
npm run dev
```

Chromiumを自動検出できない環境では、実行ファイルを明示します。

```sh
export PLAYWRIGHT_CHROMIUM_PATH="/absolute/path/to/chromium"
```

指定された4画面を、3種類の送電先を分担させて検証する例です。

```sh
npm run verify -- 1280 800 --destination lighthouse --out shots/1280x800-lighthouse
npm run verify -- 480 800 --destination train --out shots/480x800-train
npm run verify -- 1194 834 --destination city --out shots/1194x834-city
npm run verify -- 834 1194 --destination lighthouse --out shots/834x1194-lighthouse
```

各実行はスクリーンショットと `report.json` を出力します。検証内容は次の通りです。

- 8フェーズを順番に自動プレイ
- 全必須ターゲットの画面内配置、44px以上の操作領域、ドラッグ開始／終了点
- ランナー途中で縦横回転し、選択、配置数、進行を保持
- 羽根・コイルの手動配置、固定seedの補完、総数、20%容量余裕、完成円の実回転
- 潤滑油と冷却水、油面、流れ、泡
- ケーシングとクレーンの設置
- 長押し中だけ水門開度が上がり、回転速度が追従する因果
- 最初に選んだ送電先だけが点灯・動作する排他性と、設備ごとの段階的な始動順
- 完成後に水門を弱め、再び強めたときの速度・明るさの追従
- リプレイによる全状態の初期化
- ミュートUI、`aria-label`、`aria-pressed`、`aria-hidden` の同期
- コンソールエラー、page error、HTTPエラー、外部リクエストがないこと
- 実描画ジオメトリから測った人物・設備・ホース・通路・クレーン経路の衝突余白
- 横の「水→機械→送電先」と縦の「貯水→タービン→発電機→送電先」の画面内順序
- 5秒間の描画性能、renderer統計、縦横別FOV

## 性能予算

以下は自動検証の合格基準であり、実測結果ではありません。

| 指標 | 予算 |
|---|---:|
| draw callsピーク | 560以下 |
| trianglesピーク | 1,400,000以下 |
| 5秒測定の平均FPS | 30以上 |
| フレーム時間p95 | GPU 40ms以下／ソフトウェアWebGL2 55ms以下 |
| devicePixelRatio | 1.5以下 |
| 横画面FOV | 52°以下 |
| 縦画面FOV | 56°以下 |

描画品質はブラッシュドスチール、銅コイル、潤滑油、水・濡れた金属、控えめな電気発光へ集中させています。画面全体Bloom、本格的な3D流体、無制限の透明重なり、大量の動的ライトは使用しません。

## 検証結果

2026-08-27に、SwiftShaderのソフトウェアWebGL2で実行した最終結果です。各行は全8フェーズ、途中の縦横回転、最終水門の弱化／再開、リプレイまで完走し、最後に5秒間を実測しています。callsとtrianglesは一周中のrendererピークです。

| 画面 | 送電先 | 結果 | calls | triangles | FPS | p95 | console／page／HTTP／外部要求 | 回転復帰 |
|---|---|---|---:|---:|---:|---:|---|---|
| 1280×800 | lighthouse | PASS | 74 | 35,032 | 60.003 | 16.7ms | 0／0／0／0 | PASS |
| 480×800 | train | PASS | 75 | 35,104 | 60.002 | 16.7ms | 0／0／0／0 | PASS |
| 1194×834 | city | PASS | 74 | 35,032 | 60.002 | 16.7ms | 0／0／0／0 | PASS |

参考として元ゲームの検証もリポジトリ外の一時コピーで実行しました。同じSwiftShader環境では1280×800が`reveal`で620秒制限、480×800が`party`の完了待ちで制限に達し、いずれも未完走でした。制限時点の描画量はそれぞれ387 calls／712,798 triangles、351 calls／693,374 trianglesです。コンソールエラーとpage errorは両方0でした。この未完走値を元ゲームの合格結果とは扱っていません。

## 既知の制約

- 水、油、泡、発光はモバイル向けの曲線メッシュ、テクスチャスクロール、段階メッシュ、少数Sprite／Pointsによる演出で、物理流体や電気回路のシミュレーションではありません。
- 上表はソフトウェアWebGL2での再現可能なQA値です。実GPUではPBR材質と最大1.5のpixel ratioを使いますが、今回の環境では実機GPUの性能値を測定していません。
- 3〜5分は幼児が絵を見て操作する初回プレイの設計目標です。自動操作は約55〜56秒で完走しましたが、実際の4歳児を対象とする観察テストは今回の検証範囲外です。
- 看板体験にはWebGL2対応ブラウザが必要です。WebGPU専用機能には依存していません。

## 元プロジェクトの保持

参照元の `flower-decoration` は兄弟ディレクトリとしてそのまま保持します。

```text
repo/
├── flower-decoration/   # 変更しない比較用の参照実装
└── hydro-powerhouse/    # 独立した新ゲーム
```

`hydro-powerhouse` は `flower-decoration` のファイルを上書きせず、実行時にも参照しません。元ゲームは比較可能な動作・実装・検証資源として独立して残ります。
