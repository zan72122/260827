# 銀色のモビール

暗い釣り口から長い仕掛けを巻き上げると、一匹目の銀色が現れ、その下から枝糸が続き、
二匹目が現れ、さらに下に三匹目がいるかもしれない — その垂直方向の段階的なRevealだけを
中心に据えた、4歳児向けの小魚釣り作品です。iPhone / iPad の縦画面を第一級の構図として
設計しています。

得点、連掛け記録、通貨、ランキング、図鑑、課金、広告、ログインはありません。

## 動かす

```bash
npm install
npm run dev        # 開発サーバ
npm run typecheck  # 型検査
npm run build      # 型検査 + production build
npm run preview    # build 結果の確認
```

WebGL 2 が必須です。

## 遊び方

1. 画面にふれると、ドーム船の釣り座から始まります。
2. 穂先に短いアタリが出ます。水中に何匹いるかは表示されません。
3. 画面下端の電動リールの押し面を長押しすると、巻き上げが始まります。
4. 指を離すと止まり、もう一度押すと続きます。途中で止めて観察できます。
5. 全部上がったら、画面をタップすると魚外し器と観察水槽へ進み、
   魚は短く泳いだあと放流路へ戻ります。次の仕掛けが自動で水中へ戻ります。

すぐ巻いても、待ってから巻いても失敗にはなりません。待ちすぎる罰もありません。

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/game.ts` | 状態機械（deploy / wait / wind / mobile / unhook / tank）、アタリの予定、固定ステップの物理更新とrender更新の分離 |
| `src/rig.ts` | 仕掛けの力学。`lineOut` 一つの状態からリール回転・糸・枝糸・魚位置を駆動 |
| `src/fish.ts` | 小魚の体側・鰭・眼の手続き生成と材質。個体差は形態と光角度で作る |
| `src/textures.ts` | 体側／鰭／甲板／ゴム／湖面の手続きテクスチャ生成 |
| `src/water.ts` | 水面シェーダ（フレネル、波紋、水中減衰） |
| `src/scene.ts` | 船内、甲板と釣り口、竿（曲がる）、電動リール、魚外し器、観察水槽、照明 |
| `src/camera.ts` | 固定カメラ文法。自由カメラなし |
| `src/switchpad.ts` | 画面下端に別ビューポートで描く手元スイッチ |
| `src/audio.ts` | Web Audio（モーター、糸、滴、水面） |
| `src/quality.ts` | 端末に応じた初期品質と、実測 fps による適応品質 |
| `tools/check.mjs` | Playwright による通しプレイの検証とスクリーンショット取得 |

### 設計上の要点

- **魚数は巻き上げ前に確定する。** アタリが起きるたびに、待機中の仕掛けへ一匹ずつ実体が付く。
  巻き上げ中に魚が生成されることはない。
- **魚が水面を越える時刻は枝糸間隔から出る。** 位置は `lineOut` の純関数なので、
  途中停止・再開で位置が飛ばず、画面回転でも状態が保たれる。
- **暗転しない。** 巻き上げ開始から観察までカメラは連続で、結果画面もない。
- **水中は全面透明にしない。** 通常は濃紺の水面と暗い穴。魚が近づいた時だけ、
  水面のフレネルが下がる角度で薄いシルエットと銀色のspecularが現れる。
- **透明表現は観察水槽へ集中させ**、面の重なりを最小にしている（ガラスは一つの箱）。

## 既知の制約

- **WebGPU は描画には使っていない。** ゲームループは WebGL 2 のみで完結する。
  `navigator.gpu` の有無は品質段階の判定材料としてだけ使い、水滴数・魚体の反射品質・
  観察水槽の魚数を引き上げる。WebGPURenderer への移植は行っていない。
- **GLB / KTX2 / Meshopt は使っていない。** 魚体・テクスチャ・船内はすべて手続き生成で、
  外部アセットが無いため。仮素材は残していない。
- **横画面は縦画面の切り抜きではない**が、副次的な構図として、
  巻き上げ中は仕掛け全体ではなく上端側の窓を追う（糸の連続は保つ）。
- 検証はソフトウェアレンダリング（SwiftShader）上の Chromium で行っているため、
  実機の実測フレームレートは測っていない。
