# HE染色シミュレーター

正常ヒト大腸のパラフィン切片（教材上 4 µm）を **1 枚だけ**載せたスライドを、自分の手で H&E 染色し、
完成標本の顕微鏡画像を観察して、**自分の操作履歴と照らして原因を考える**ための Web 教材です。
スマートフォン縦画面（iPhone のブラウザ）を最優先に設計しています。

「正しい薬液を順番に押すと決まった画像が出る」教材ではありません。
タッチ操作 → 器具の動き → 薬液への曝露 → 標本の状態変化 → 同じ組織視野の染色像 → 根拠付きの振り返り、
という因果の連鎖が実際に通っています。

- 手順の基準: Newcomer Supply「H&E STAINING PROCEDURE WITH HARRIS MODIFIED」（→ [PROTOCOL.md](PROTOCOL.md)）
- 素材と出典: → [SOURCE_MANIFEST.md](SOURCE_MANIFEST.md)

> **この教材が主張しないこと**
> 実作業の力量認定教材ではありません。臨床用の染色品質予測器でもありません。
> 完成画像は染色状態の**教育用シミュレーション**であり、各条件で実際に染めた対照標本の写真ではありません。
> 医学的妥当性について専門家のレビューは受けていません。

## 起動方法

必要なもの: Node.js 20 以上（開発は 22.22 で確認）。バックエンド・ログイン・API キーは不要です。

```bash
npm install
npm run dev          # http://127.0.0.1:5173/ が開発サーバー
```

本番ビルドと確認:

```bash
npm run build        # 型検査 + dist/ の生成
npm run preview      # http://127.0.0.1:4173/
```

### 顕微鏡画像の実写素材（任意）

完成画像の基礎に使う実写の顕微鏡写真は、ライセンス上の理由からリポジトリに同梱していません。

```bash
npm run fetch-assets
```

を実行すると Wikimedia Commons の *Colon, high mag.jpg*（CoRus13 / CC BY-SA 4.0）を
`public/assets/tissue/` へ取得し、クレジットを含む `manifest.json` を書き出します。
取得に成功していれば、起動時に自動的に実写経路（色分離 → 状態に応じた再合成）が使われます。

**取得できない環境では、実写ではない「構造模式図」で代替します。**
偽の組織画像を実写として扱うことはなく、タイトル画面・メニュー・完成画像のキャプションで毎回明示します。
（この実装環境では取得できませんでした。詳細は [SOURCE_MANIFEST.md](SOURCE_MANIFEST.md) B 節）

## 操作方法

### 画面

- 上部: 工程名／モード／教材内経過と実操作時間／現在の槽の名前と原手順の条件／浸漬の状態
- 中央: 作業台（3D）。ここでラックを操作します
- 下部: 親指で押す操作列（工程の移動、水の交換、学習用拡大、手順書、メニュー）

### ラックの操作（すべてタッチ）

| したいこと | 操作 |
|-----------|------|
| ラックをつかむ | 取っ手の少し下あたりを押さえる（指で器具が隠れないよう、ラックは指の少し上に表示されます） |
| 沈める／引き上げる | つかんだまま上下にドラッグ |
| 隣の槽へ移す | つかんだまま左右に大きくドラッグ（縁に当たらないよう自動で持ち上がります） |
| 別の槽を選ぶ | 槽をタップ |
| 液切り | 槽の上に保持したまま待つ。液膜が薄くなり、滴が元の槽へ戻ります |
| 水を交換 | 水洗の工程で、ラックを上げてから「水を交換」 |
| 別の工程へ | 下部の ◀ ▶ |

**ディップは往復の回数で数えます。** 指の細かい震えや pointermove の数では増えません。
切片全体を液面下まで沈めてから、液面より上まで引き上げて 1 回です。

### 時間の扱い

- **操作時間**（指の動き、ラック速度、滴下、カバーガラス）は常に等倍です。
- **教材内モデル時間**は、静かに沈めたまま 1 秒以上待っているときだけ最大 ×10 に加速します。
  加速中は上部に「×10 加速中」と出ます。ディップ中は加速しないので、回数が水増しされることはありません。
- **分別（酸アルコール）は加速しません。** 目安に達しても自動では引き上げません。引き上げるのは常にプレイヤーです。
- 説明画面を開いている間、タブが非表示の間、画面回転の処理中は時計が止まります。

### 封入

1. 「ラックから同じスライドを取り出す」
2. **押し出す**: 画面をドラッグして容器の位置を決め、その場で押さえ続けると封入剤が出ます（押した時間で量が変わります）
3. **接触位置**: 上下ドラッグでカバーガラスの一辺の位置を決め、「この位置で下ろす」
4. **下ろす**: 下へドラッグして倒します。**下ろす速さで気泡の出方が変わります**

### モード

- **練習モード**: 最初の 1 動作だけ案内します。メニューから「誤操作を止める」（手順から外れる前に確認）と
  「巻き戻し」（標本・槽・履歴を矛盾なく戻す教材機能）を使えます。
- **実践モード**: 正しい薬液も原因も先には表示しません。手順書・薬液名・時計は参照できます。
  誤った順序も選べます。最終画像まで進んでから考えます。

**両モードで化学・封入のモデルは同一です。** 変わるのは案内とフィードバックのタイミングだけです。

### 学習用拡大表示

肉眼では見えない切片内部の状態（残存パラフィン、色素量、濡れ、乾燥など）を補助表示します。
**顕微鏡を覗いている表示ではありません。**
「自動 / 必要時に開く / 非表示」を選べます。**「非表示」では DOM にも情報を出しません**（実践モードで答えが透けません）。

### 封入後の流れ

1. 完成画像を大きく表示（拡大・パンできます）
2. 所見を選ぶ（「大きな問題なし」も選べます）
3. 原因候補と、根拠になりそうな操作を選ぶ
4. 実際の操作履歴と標本状態を重ねた解説を開示
5. 次に変える 1 条件を選び、モデル上の反実仮想比較、またはその工程からの再練習へ

評価は「観察できた所見」「履歴に基づく原因推定」「修正の妥当性」を分けて示します。
工程完了率や満点の演出には置き換えていません。
また「画像だけから考えられる複数の原因候補」と「今回の履歴から特に支持される原因」を区別して説明します。

## 開発

```bash
npm run typecheck    # tsc --noEmit
npm test             # 因果モデルの単体テスト（vitest）
npm run e2e          # 実際のポインタ操作を通す操作テスト（Playwright）
```

- **単体テスト**（`test/unit/`）は内部状態へ直接アクセスして因果モデルを検証します。
- **操作テスト**（`test/e2e/`）は実際のポインタ経路とボタンだけで進めます。
  ページ側が公開する `window.__he` は**読み取り専用**（座標と現在値を返すだけ）で、
  状態を書き換える手段は公開していません。内部状態を書き換えて終わらせたものを完遂の証拠にはしていません。
- 取得した画面と画像は `evidence/` に置いています。

### ディレクトリ

```
src/sim/       標本状態モデル・化学・封入の幾何・操作ログ・振り返りの判定（描画から独立）
src/micro/     色分離と完成画像の生成（基礎版の読み込み、模式図の生成、合成）
src/render3d/  three.js のシーン（槽・ラック・スライド・封入台・材質）
src/app/       ゲーム進行、2 種類の時計、描画品質、効果音
src/ui/        画面（HUD、手順書、学習用拡大表示、顕微鏡表示、振り返り）
test/unit/     因果モデルの単体テスト
test/e2e/      ポインタ操作の完遂テスト
evidence/      取得した画面・画像
```

### 設計上の要点

- **標本状態は描画から独立**しています。`src/sim/` は DOM も three.js も参照しません。
- 標本は 20 × 14 の 2D 状態マップで、行が切片の高さに対応します。
  液面より上だった行は実際にその位置で反応が不足します。
- **1 プレイの入力は tick 列（槽・浸漬レベル）として記録**され、同じログと seed からは必ず同じ結果が再生されます。
  反実仮想はこのログを 1 箇所だけ書き換えて再生したものです。
- 完成画像は色分離した H / E 成分を状態モデルに応じて増減して再合成します。
  RGB 全体の色相回転や彩度操作、照明演出やカラーグレーディングは使っていません。
  気泡・未充填・曇りは組織を書き換えず、光学的な観察妨害としてのみ重ねます。

## 確認した環境と、確認していないこと

**確認できたこと**

- ビルド: `tsc --noEmit` と `vite build` が通ること（配信サイズ gzip 約 168 KB）
- 因果モデル: `npm test` の 20 件（下記の受け入れ条件 2〜7 に対応）
- 操作: Chromium 141（`/opt/pw-browsers/chromium-1194`、SwiftShader によるソフトウェア WebGL）を
  390×844 / 375×667 / 430×932 のモバイルエミュレーションで動かし、
  実際のポインタ操作で工程の完遂・pointercancel・中断復帰・画面回転・連続再挑戦を確認

**確認していないこと（重要）**

- **実機 iPhone / WebKit では一切検証していません。** この環境には WebKit が入っておらず、
  Chromium しか利用できませんでした。モバイルエミュレーションの結果は実機検証ではありません。
- **性能は計測していません。** ソフトウェア WebGL 上では 30fps に届きません。
  30fps 以上という目標は設計目標であり、実機での保証値ではありません。
- 医学的妥当性について専門家の評価を受けていません。
- 実写の顕微鏡画像を使った表示経路は、画像を取得できていないため実データでは動かしていません
  （コード経路とライセンス表記は実装済みです）。
