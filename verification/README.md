# 検証記録

production build (`npm run build` → `vite preview`) を Chromium
（モバイルビューポート・タッチ有効・SwiftShaderソフトウェアGL）で実プレイして検証した。
実行方法は `node test/verify.mjs`（全構成）/ `--devices` / `--shapes` / `--quick`。

## 1. 検証契約の6形状（+ベンチ用短弧）

`test/shapes.mjs` の6形状（手描き相当のジッタ入り）を実入力パイプラインへ流し、
全て compare フェーズまで完走。`report.json` に統計を記録。

| 形状 | 判定 | 層 | 経路長 | 結果 |
|---|---|---|---|---|
| 円に近い閉曲線 | closed | 90/90 | 8.0m | 円形の壁 |
| 横長の楕円 | closed | 90/90 | 8.4m | 横長楕円の壁 |
| 緩いS字 | open | 90/90 | 4.8m | S字の開放壁（両端テーパー） |
| 右膨らみ | closed | 90/90 | 7.6m | 右へ延びた非対称壁 |
| 左膨らみ | closed | 90/90 | 7.6m | 左へ延びた非対称壁（右膨らみの鏡像） |
| 丸角四角形 | closed | 90/90 | 9.2m | 角丸スクエアの壁 |
| （短い弧） | open/bench | 26/26 | 1.6m | 庭園ベンチ |

- すべて別形状の壁になり、同一テンプレートへの置換なし
- 開閉判定・ベンチ判定は入力どおり
- スクリーンショット: `shots/shape-*-4-complete.png`

## 2. ブラインド形状推定（新しい文脈の検証担当）

比較カード・ファイル名を隠した俯瞰画像6枚（`blind/A..F.png`）を、実装を知らない
別エージェントに渡し「元の一筆」を推定させた。

- 円 / 横長楕円 / 開いたS字 / 丸角四角形: **即確定（確信度: 高）**
- 右膨らみ / 左膨らみ: 両者が鏡像関係であることを正しく知覚
  （「Aは左に尖った突起・Eは右に尖った突起」= 正解キーと一致する左右差の記述）。
  ただし「膨らみ」という語を延長側でなく丸い側と解釈したため、ラベルの割り当てのみ逆。
  ピクセル座標が同一パイプラインを素通りするため、鏡像反転は構造上起こらない
  （数値検証: 経路のcentroid偏差が入力どおり左右対称に出ることを確認）。

結論: **6形状すべて相互判別可能で、軌跡の形状・左右差は壁に保存されている。**

## 3. 幾何・資源の検証

- 層の浮きなし: 各リングの下端が層基準より1.3mm食い込み（`debugExtents`: y0=0.1487 < スラブ天端0.15）
- ノズルとビードの隙間なし: ライブリングがノズル直下でメニスカス状に接続
- 角での瞬間旋回なし: 前後パスの台形送り速度計画（丸口ノズルのため回転自体が不要）
- 端面: taper→0 で断面がほぼ点に収束し閉じる
- 巻き方向: 全チューブ系ジオメトリの表裏を修正済み（黒潰れの根本原因だった）
- 再プレイ: geometries 262→247・rings 16200→0（GPUリソース解放を `renderer.info` で確認）
- 回転: 積層中に縦→横→縦へ回転しても経路・層・進行を保持（`test/rotate.mjs`: OK）
- 長経路: 丸角四角 9.2m×90層 = 総リング18,630・約37.8万tri・draw call ~12バッチで完走

## 4. デバイス×縦横の通しプレイ — 全構成エラー0で完走

iPhone(390×844)/iPad(834×1194) の縦横4構成すべてで、
入力中→第1層→積層→完成(compare) の通しプレイが完走し、
16枚のスクリーンショットを `shots/<device>-circleish-*.png` に保存した。

- 4構成とも rings 16,200 / 約33万tri で一致（構成間で生成結果が同一）
- iPhone縦では再プレイ検証も実施: geometries 262→247・rings→0（解放確認）
- 縦は「手前から奥へ続く壁と高さ」、横は「ガントリー全幅と曲線壁」の別フレーミング
- 第1層の横画面ショットでは、赤いケール線（子どもの線）→墨出し線→
  ノズル→湿潤ビードの因果が1画面で読める
（SwiftShader環境はフレームレートが実機より大幅に低いため、
 homing に開始保証のセーフティネットを追加した上で検証）

## 既知の制約

- 検証はChromium/SwiftShader上のモバイルエミュレーション。実機Safariでの最終確認は
  実機で `npm run preview` のURLを開くこと（WebGL2・Pointer Events・100dvh対応済み）。
- タイムラプス中の見せ場減速は 16層周期の角でのみ発生（全周減速はテンポを損なうため）。
